# 开发限制与实现约束（原型 → 真实代码）

这里记录**原型阶段暴露出来、真实实现必须解决或保留的约束**。原型负责把交互和产品逻辑定型，真实代码按这份清单完善，可以少走弯路。约定随原型推进持续追加，不回填历史。

---

## 1. 导航与路由（当前最大的卡顿来源）

- **原型是多页应用**：每次跳转——包括侧栏「返回上一级」、切换经典/影院、点充值——都是整页重载，网络往返加重渲染是可感知的卡顿。原型层只能靠三件事缓解：
  1. 悬停预取目标页 HTML（`pointerover` + `fetch`，见 `mount()` 里的导航助手）；
  2. 进设置前把来源写进 `sessionStorage['rp-settings-return']`，「返回上一级」直接 `location.href` 回跳，不走 `history.back()`（新标签打开时 back 无效，兜底定时器还会把慢导航劫持到首页——第一版踩过）；
  3. 页面进场淡入（`immersive.css §51`），把「白屏闪烁」变成过渡。
- **真实代码必须做成 SPA 路由**：
  - 切换不再重载；转场用 View Transitions API（`document.startViewTransition`），淡入淡出兜底；
  - 路由级预取：不只预取 HTML，还要预取该路由的数据（角色、会话、点数用量）；
  - 返回上一级 = 路由状态栈回退，无历史时回首页的兜底要保留；
  - `prefers-reduced-motion` 时关闭全部转场。

## 2. 弹层与菜单

- **悬停展开 + 点击 toggle 会互相打架**（悬停刚打开，点击又关上）。定稿的语义：悬停临时展开、点击钉住、再点关闭、Esc / 点击外部关闭、ArrowDown 进入面板。真实代码封装成统一 Popover 组件（focus trap、`aria-expanded`、外点关闭），不要每个面板各写一套。
- **点数面板**的分项（文本对话 / 生图 / 语音）来自服务端用量接口。未开启的能力展示「未开启 + 单价」，**不得伪造用量**；点数记录的余额链必须能对上（每条 `balance` = 上一条 balance + amount）。
- 模型回复、生图、语音、支付、审核在原型里均为本地模拟或未接入；任何面板与文案都要与真实能力区分（「本地演示」「未实现」标注），真实代码接入时只替换数据源，结构与文案骨架保留。

## 3. 分区侧栏模式

- 「我的」页的定稿模式：进入后主站侧栏替换为分区目录，顶部「返回上一级」，正文通栏；滚动时侧栏分区高亮跟随（140px 阈值）；手机端侧栏不显示，横向目录条保留。
- 原型实现要点：目录定义收敛在 `settingsSections` 一处；scroll 监听在重渲染前移除旧 handler（`settingsSpy`）；`scrollIntoView` 平滑滚动 + `history.replaceState` 写 hash；绑定去重（`data-smooth-bound`）。
- **真实代码**：滚动联动用 IntersectionObserver；侧栏容器跨路由复用而不是每页重画；该模式可复用到创作、角色库等有内部分区的页面。
- 返回按钮的可用性：hover 即预取来源页，点击后目标已在缓存里。

## 4. 状态与存档

- 原型状态在 `sessionStorage` 当前标签页（`rp-platform-state` v2），历史存档先备份再迁移，失败不得假报成功。
- **真实代码**：服务端为唯一数据源，本地只做缓存与草稿；乐观更新必须带回滚；跨设备同步点数与用量以服务端账单为准，前端不得自行推算余额。

## 5. 双视图与样式层级

- 经典 / 影院两套皮肤共用一套 DOM 与交互逻辑，只有 CSS 分层（`cinema.css`、`immersive.css`），选择器用 `body[data-page]:not(.p-cinema)` 区分。**改交互时两个视图都要验**。
- 样式优先级容易互相渗透：为右栏写的规则会漏进弹窗（nowrap 截断、section 去 padding 都踩过）。新规则一律收进最小作用域，弹窗内的规则用 `.p-modal` 限定。

## 6. 工程纪律（原型层）

- 改 `platform.js` / 任意 CSS 必须全页 bump 版本号（11 个 HTML 同步）；CSS 与 JS 版本独立递增。
- 验证流程：`node --test platform.test.cjs rp-state.test.cjs tests/*.test.cjs tests/*.test.mjs` 全量（当前 275 项）+ 无头 Chrome 实机截图与交互验证；单测不能替代视觉与移动端验收。
- CDP 验证的坑：只 `Page.enable` 时 `Network.setCacheDisabled` 不生效，会拿到上一版资源造成误判；必须先 `Network.enable`，必要时 `Page.reload({ ignoreCache: true })`。
- 测试沙箱的假 `document` 缺标准 API（`getElementById`、`removeEventListener` 已补；`getBoundingClientRect` 缺失时生产代码需存在性守卫）。生产代码新增对宿主 API 的依赖时，同步补 mock。

## 7. 错误与反馈通道（2026-11-07 全站审计后定稿）

- 破坏性操作（删除身份/作品/房间/会话/消息）：确认弹窗（confirmAction），文案说明后果与是否可恢复。
- 轻量成功/失败提示：toast（4.2s 自动消失）；失败额外带 `err` 样式。
- 表单校验：行内 `p-form-error`，不使用弹窗。
- 撤销类操作：行内撤销条（如角色库移除），不走确认弹窗。
- 三种通道不要混用；新增交互前先按这个规则选通道。

- 目前并存：proto 1023、platform-pages 1199/960/720、polish 1180/1100/960/720、immersive 1180/720/560、auth 1199/959、admin 960/720/560。

## 9. RP 功能缺口路线图（对照 SillyTavern 1.19.0，2026-11-07 审计）

高：自动摘要（记忆引擎）；向量记忆/RAG；服务端持久化与多用户（真实代码阶段）。
已落地（2026-11-07）：消息富文本渲染（`renderMarkdownBlocks`：加粗/斜体/删除线/行内代码/代码块/引用/列表/表格/分隔线 + 【状态】卡片 + `<think>` 折叠 + 白名单 HTML 表格；全部先 esc 再还原有限标记，未认识的 HTML 以原文显示）——真实代码换成 sanitize-html + marked 时保持同样的白名单边界与「先转义」顺序；群聊激活策略对齐——natural（@提及优先，无提及按顺序）/ round-robin（顺序 LIST）/ manual（手动指定）/ pooled（随机一位）/ free（全员各一次），成员静音（muted，@也不点名）、auto-mode 自动推进（首轮后按顺序再让最多两位接话）、房间消息操作（复制/编辑/删除，DOM 契约与单聊对齐 .p-msg）、房间输入区 .p-compose-bar 结构 + 代写一句 + 插入旁白 + @点名。
真实代码注意：pooled 目前是等权随机，接入 talkativeness 权重即可；auto-mode 原型是同步追加，真实实现改为逐条延时 + 可中断。
中：TTS/STT、图像生成（需真实服务）。
已落地（2026-11-08）：记忆检索（向量检索的本地近似）——`ragChunks` 用中文字符 bigram 重叠做相似度，查询=最新一条玩家输入，从「最近消息」之前的历史里取 topK（默认 3、可 1–5）片段，至少命中 2 个 bigram 才算相关；`promptBlockText('rag')` 生成「记忆检索」块（自动摘要之后）；记忆弹窗可开关与调条数。真实代码换成 embedding + 向量库时，保持「查询=最新玩家输入、返回 topK 片段」的接口即可。
已落地（2026-11-08）：角色表情——沿用 ST 的 default-expressions 通用表情图（`assets/expressions/`，角色没有专属立绘时 ST 也用它），情绪由本地关键词分类（`classifyEmotion`，非模型判断），只在非「平静」时在消息名旁显示表情；角色有专属表情图后把 `<emotion>.png` 换成 `<角色>-<emotion>.png` 即可。
已落地（2026-11-08）：instruct 序列与上下文模板——`preset.contextTemplate`（占位符 {{char}}/{{hook}}/{{description}}/{{personality}}/{{scenario}}/{{legacy}}/{{instructions}}，空值整行省略）决定角色块组装；`preset.instruct`（enabled + input/output/system/stop）按消息角色包装历史行、末尾追加停止序列；ST 预设导入把 story_string（去 handlebars 条件）与 input/output/system/stop_sequence 映射进来。序列是精确字符串，保存时不能 trim。
已落地（2026-11-08）：采样参数完整度——preset.params 扩到 temperature/top_p/top_k/min_p/typical_p/rep_pen(+range/slope)/presence_penalty/frequency_penalty/max_tokens/seed 共 12 项，预设编辑器「高级采样」折叠区可调，ST 预设导入映射同名与别名（rep_pen/presence_pen/freq_pen/n_predict）；真实接入时按这套字段下发即可。
已落地（2026-11-07）：聊天内搜索、书签/检查点、自动备份+恢复+txt 导出。
中低/低：全局正则 alter-chat、QR 自动执行、斜杠管道与嵌套、消息批量操作、消息附件、主题/CSS 自定义、聊天背景图、时间戳/思考块、auto-swipe、逐块 token 预算。

## 10. 模拟边界清单（2026-11-09 收口）

原型里每一个「看起来能用、实际是本地模拟」的地方，都必须有可见标注。真实代码按这张表逐项替换实现，标注随之删除或改写。

| 功能面 | 当前实现 | 界面标注位置 | 真实代码要做 |
|---|---|---|---|
| 角色回复 | 本地模板回复，不调用模型 | 聊天页顶部状态条「本地模拟 · 模板回复 · 不调用模型 / 不扣点」；消息名「· 模板模拟」 | 接模型网关，删掉状态条与「模板模拟」 |
| 房间回复 | 同上 + 策略调度 | 房间页状态条「本地模拟 · 不调用模型，不扣点 · 多角色，不是多人在线聊天」 | 多角色生成与调度 |
| 上下文预览 | 本地组装 | 弹窗首行「本地演示引擎 · 未发送给真实模型」 | 接真实提示词与分词 |
| 采样参数 | 只存配置 | 预设编辑器「本原型不调用模型，参数不会真正生效」 | 按 params 下发采样参数 |
| 自动摘要 | 抽取式（关键词行） | 块名与摘要首行「本地抽取式摘要 · 非模型总结」 | 接模型摘要，保留覆盖/触发语义 |

| 支付/卡密 | 未接入 | 「未实现」弹窗 | 支付网关与卡密服务 |
