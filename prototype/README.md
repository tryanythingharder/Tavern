# 酒馆 v2 · 界面原型说明

这是一版**可交互的玩家端 RP 平台原型**。12 个玩家页面 + 可切换的管理后台，无构建步骤，Three.js 已本地化。登录页使用与正式实现一致的雨夜房间场景；发现、广场、角色详情和作者主页支持「经典 / 影院」双模式，工具页保持清晰的产品层级。

打开 `index.html` 查看总览；玩家端通过 `platform.js` 共享当前标签页内的角色、会话、收藏、身份与房间状态。**原型没有请求真实模型、支付或用户后端**，不能把演示成功理解为线上接口已验收。

当前验收不能等同于“成熟平台”。2026-11-02 第二轮已由三个子代理分别实现物理动效、十页视觉层和 RP 保存闭环：身份、文本草稿、私人试聊、房间消息及策略现在能在同一标签页跨刷新回读。旧存档先备份再迁移至 v2，失败不假报成功。模型、审核、支付仍为未接入/本地模拟；图片仍仅当页预览，导入与完整备份恢复待实现。初次问题清单见 [历史复检](REVIEW-20261102.md)，**本轮交付与证据以 [第二轮验收](REVIEW-20261102-PASS2.md) 为准**。

**开发限制与实现约束见 [DEV-CONSTRAINTS.md](DEV-CONSTRAINTS.md)**：原型阶段暴露、真实代码必须解决或保留的导航/弹层/侧栏/状态约束，做真实实现前先读这份。

**真实实现方案见 [IMPLEMENTATION-PLAN.md](IMPLEMENTATION-PLAN.md)**：技术选型、前端路由、后端接口、数据模型、生成流水线与分阶段交付（M0–M4）。

每个页面只有**自己的排版**写在文件内的 `<style>` 里；颜色、圆角、间距、字号、按钮长相全部来自 `proto.css`。登录页例外：独立使用 `auth.css`，与正式认证的 `cai-auth.css` 同步，不加载玩家端的 `cai-shell.css`。

**改法约定**：
- 想换整体气质 → 只改 `proto.css` 顶部 `:root`
- 想换组件长相 → 只改 `proto.css` 里对应的 `.p-btn` / `.p-card` / `.p-field` / `.p-pill`
- 想换某页排版 → 只改那个页面 HTML 里的 `<style>`

## 2. 设计系统（这一版真正解决的事）

现状最大的问题不是"不好看"，是**没有系统**：审计出 20 种圆角、26 种阴影、16 种按钮、7 种卡片、8 种输入框、28 个字号，三套颜色令牌互不引用。

### 2.1 视觉方向：经典 / 影院双模式（2026-10-28）

叙事页顶栏有一个「经典 / 影院」分段开关，选择写入 `localStorage.rp-view-mode`，切换后当前页原地重渲染，不跳页：

- **经典模式**：保留暖纸色、宋体标题、全幅场景 Hero、3:4 角色卡和原有广场卡片；这是之前的默认外观。
- **影院模式**：参考的是 Ravi Klaassens 的 A24 概念站 `https://a24.raviklaassens.com/`，不是 `a24films.com` 官方站。发现页以浅纸色、左上角色资料、紧凑居中导航和真实 WebGL 光盘呈现。底部展示当前角色的公开简介和互动节奏，不伪造媒体短评或五星评分。视觉为本地化设计，不宣称与原站逐像素一致。
- **广场影院模式**：白底、左上当前作品信息、可拖拽旋转的 Three.js 光盘阵列；搜索、排序、题材筛选、NSFW 同意、导入/创建入口都保留。
- **详情影院模式**：全幅黑白剧照、超大无衬线角色名、入场黑幕；内容区改为白底，主内容在左、统计与开始对话在右；旧的双栏封面/标题隐藏，开场、身份、评论等交互全部保留。
- **转场**：光盘点击先150ms真实3D预压，再220ms纸色淡出进入详情；不再拉伸成灰色整屏。海报仍使用短封面过渡，详情幕布320ms。`prefers-reduced-motion` 下跳过动态，直接导航。
- **3D 光盘**：盘位来自围绕当前索引的弧线与透视。桌面拖住当前盘时单独旋转，松手回弹；背景拖动和手机横滑浏览。滚轮、方向键、前后按钮、作品索引换片，空格翻面，点击当前盘或 Enter 进入详情。解析阻尼弹簧保留速度和惯性，换片有受限侧倾与下压；当前盘悬停有俯仰/清漆高光和双细线轮廓。约575ms一次入场、150ms预压；静止停RAF、隐藏暂停、减少动态直接落稳、销毁清理完整。
- **成人向门禁**：NSFW 角色在未开启前，经典卡片、海报、光盘、作品行、首页 Hero、详情剧照统一模糊并显示 18+ 遮罩。
- **场景资源**：`scenes` 是指向 `SillyTavern/default/content/backgrounds` 的软链接；原型只读取本地背景图，不引入 CDN 或外部字体。

工具页（聊天、会话、创作、设置、后台）不加载 `cinema.css`，继续使用原有紧凑布局。

回归命令：`node --test platform.test.cjs rp-state.test.cjs tests/disc-gallery.test.mjs tests/disc-motion.test.mjs`。第二轮74项通过：旧状态12项、保存闭环17项、画廊与运动45项。它们覆盖真实业务函数/Three几何，DOM、RAF和GPU用测试替身；不覆盖后端、视觉相似度、真机GPU功耗或真实模型生成，不能代替浏览器验收。动态录像与逐帧图放在 `review-artifacts/`。

## 3. 逐页：改了什么、为什么、落到哪

### 3.1 登录 / 注册 · `login.html`

**现状问题**（`public/login.html` + `scripts/cai-login.js` + `cai-shell.css:3839-4139`）
- 品牌为零：`.cai-auth-brand` 内容就是纯文本 `(酒馆)`，整套产品唯一的品牌符号反而只存在于后台（`admin.css:72-84`）
- 首屏会闪出上游 SillyTavern 的「Welcome / 选择账号」和别人的头像列表，因为隐藏要等 `/api/cai/config` + `/csrf-token` 返回后才加 `body.cai-auth-ready`
- 「忘记密码」永远点不到：`#passwordEntryBlock` 在 `#userListBlock` 里，而后者被 `display:none !important` 永久隐藏
- 报错时错误框 `min-height:0`，按钮会往下跳 22px
- 中文用户名被 `slugifyHandle` 静默清空，只提示"请输入小写字母"，不说输入已被改写

**v2 改法（2026-10-27 已落地）**
- 参考 Character.AI 真实公开认证页：顶部品牌与登录/注册切换，400px 白色悬浮认证卡覆盖在完整故事场景上，而非左右分栏
- 默认注册引导，点击展开字段；独立登录视图，邀请码按服务端配置显示
- 字段 48px、按钮 48px、圆角 12px；保留 inline 校验、密码显隐、提交 busy、接口错误
- 注册仍调用 `/api/cai/register` 并自动登录；开放注册不强制邀请码
- 忘记密码明确引导管理员重置，不伪造邮箱找回流程
- 移动端保留淡化的场景背景与白色悬浮卡，认证表单整页滚动；320px 无卡内滚动条、无横向溢出
- 初始化失败显示可重试错误，不再注入或闪现上游用户列表

**落地位置**：`public/login.html` 静态骨架 + `scripts/cai-login.js` + 独立 `css/cai-auth.css`；场景为 `img/cai-auth-scene.jpg`（项目内置房间背景的低饱和调色版本）。登录页不再加载原生 `scripts/login.js` 或 `cai-shell.css`。
**难度**：中（静态骨架与认证逻辑已重构，后续只需替换场景图或调整认证令牌）

### 3.2 发现（首页）· `home.html`

**现状问题**（`cai-app.js:1630/1740/1858/1973`、`cai-shell.css:745/3012`）
- 英雄位和「精选推荐」第一张卡是同一个角色：`pickFeaturedCharacter` 从 recommended 取，`buildRecGrid(recommended)` 又整段渲染——同一张脸连续出现两次
- 英雄位点击直接开聊，普通卡片点击进详情，同一个网格两种导航语义
- 对话入口 4 个：侧栏、首页「继续对话」、对话 tab、详情页「继续上次对话」
- 移动端要滚约 1300px 才到「全部角色」，而吸顶筛选区占 667px 屏高的 18% 且背景不透明
- 所有 `<img>` 没有 `onerror`，破图直接露浏览器图标

**v2 改法**
- 顺序固定：主视觉（240px，点击进详情）→ 标签 → 继续上次的故事（横向 4 张紧凑卡）→ 编辑精选（横向书架，**排除主视觉那个角色**）→ 全部角色（6 列网格）
- 删掉与主视觉重复的「精选推荐」整段网格
- 卡片统一：3:4 封面 + 名称 14px + 作者 12px + 两行简介（固定 2.9em）+ 底部状态行（`margin-top:auto` 保证对齐）
- 封面兜底：没有图就用 `--h` 色相生成渐变 + 首字（`data-initial`），永不出现破图
- 「继续对话」保留但压缩成一行，不再和对话 tab 抢语义

**落地位置**：`cai-app.js` 的 `renderHome` / `buildRecGrid` / `pickFeaturedCharacter`，`cai-shell.css:745` 起的 `.cai-feature`
**难度**：中（删段 + 调顺序在渲染函数里改，卡片样式是纯 CSS）

### 3.3 广场 · `plaza.html`

**现状问题**（`cai-shell.css:3492/3494/4728`、`cai-app.js:762-790/906-925/997`）
- `.cai-plaza-sort` 是 `inline-flex`，`.cai-nsfw-toggle{margin-left:auto}` 在没剩余空间时不生效，NSFW 紧贴「最热」只有 4px
- 全页没有吸顶，滚过 24 张卡（约 1400px）后搜索/排序/NSFW 全部离屏
- 标签 chips 由已加载数据统计，翻页后数量与顺序会跳；选中标签后「剩余 N」仍用未过滤的 total，数字是错的
- 分页失败静默：`items=[]` + `hasMore=false`，「加载更多」直接消失，没有错误态
- 和首页卡片不一致：广场卡无收藏按钮，状态角标位置也不同

**v2 改法**
- 筛选条吸顶在顶栏下方：第一行「全部/最新/最热」+ NSFW + 计数，第二行标签 chips 横向滚动
- 卡片与首页共用同一套 `.p-work`：NSFW 右上、已添加 左下、收藏 右下，三个位置固定
- 失败态：保留旧卡片 + 底部内联错误条，而不是整段消失
- 桌面 4 列 → 1200px 以下 3 列 → 900px 以下 2 列

**落地位置**：`cai-app.js` 的 `renderPlaza`，`cai-shell.css:3492` 起的 `.cai-plaza-sort` / `.cai-chips`
**难度**：中（吸顶是 CSS；标签统计和 total 的错要改渲染逻辑）

### 3.4 角色详情 · `character.html`

**现状问题**（`cai-app.js:2370-2385/2445-2536`、`cai-shell.css:919/934/1109/1133`）
- 三个「开始」入口：hero 主按钮、输入框、看起来可点的开场白气泡
- 输入框无条件 `doNewChat`，即使有历史会话——每次进来点一下都新建，绕过「继续上次对话」
- 「返回广场」实际跳首页，文案与行为不符
- `#cai-detail-stats` 是空 div 异步填充，hero 高度会跳变
- 780px 内容宽配 180px 封面，桌面右半空；而广场是 920，首页 1080，三种栏宽
- 备用开场白全量展开，20 条时页面 4000px+
- 移动端 CTA 滚出屏幕后没有固定操作条

**v2 改法**
- 桌面两列：左栏粘性资料卡（封面 / 名称 / 作者 / 标签 / 统计 / 继续或开始 / 收藏+更多），右栏公开设定、开场与身份
- 有历史时主操作是「继续最近对话」，新故事独立入口；同角色可查看全部会话
- 设定三张卡合并成一张，性格/场景/创作者备注降为 h4
- 备用开场白默认 2 条 + 「展开全部 12 条」
- 移动端：封面缩成 96px 放在标题旁，底部固定 64px 操作条

**落地位置**：`cai-app.js` 的 `renderCharacter`，`cai-shell.css:919` 的 `.cai-detail` / `:934` 的 `.cai-back`
**难度**：中（布局是 CSS，删入口和改 `doNewChat` 逻辑要动 JS）

## 4. 哪些能改、哪些要掂量

### 可以自由改（只碰 CSS，零风险）

- 颜色、圆角、阴影、间距、字号 —— 改 `proto.css` 的 `:root`
- 按钮/卡片/输入框/胶囊的长相 —— 改 `proto.css` 的组件 recipe
- 某一页的排版、栏宽、列数、断点 —— 改该页 HTML 的 `<style>`
- 卡片的封面比例、简介行数、角标位置
- 深浅色：加一组 `[data-theme="dark"]` 覆盖 `:root` 即可，因为所有颜色都走令牌

### 改之前要确认（会动渲染逻辑，但不碰后端）

- 页面上模块的**顺序**和**增删**（例如首页删掉「精选推荐」）
- 卡片点击是进详情还是直接开聊
- 入口收敛（把 4 个聊天入口收到 1–2 个）
- 设置页的分组与目录项
- 后台表格在移动端换成卡片列表

这些都在 `cai-app.js` / `admin.js` 的 render 函数里，改完要回归一次「角色卡 / 世界书 / 预设 / 正则 / 滑动重生成」是否还正常。

### 不建议动（会破坏现有能力或超出这次范围）

- **不要重写成 React/Vue**：整套提示词引擎（世界书、预设、正则、上下文模板）挂在原生 DOM 上，换框架等于重做后端
- **不要改 ST 原生消息渲染的 DOM 结构和 id**（`#chat`、`.mes`、`#send_form`、`#sheld`），扩展和滑动依赖它们
- **不要动** `world_info` / `presets` / `regex` 的存储格式和字段名
- **不要**在玩家端做"隐藏 API 配置"以外的安全假设——真正的边界是服务端网关 + 模型白名单
- 保留 AGPL-3.0 头和上游可合并性

### 原型里刻意没做的

- **真实角色图片**：叙事页使用本地场景图（`scenes/` 软链接），加载失败时自动移除图片并回落到 CSS 渐变 + 首字；工具页仍以渐变封面为主。真实实现时把同一套 `<img>` + `onerror` 逻辑映射到后端角色封面即可。
- **动效**：经典模式保留 120/160/240ms 三档过渡；影院模式额外有光盘悬停、作品行放大、封面扩展转场和详情入场黑幕，`prefers-reduced-motion` 下全部跳过。
- **后台分页/搜索**：原型是静态的，真要做需要给 `/admin-orders` 等接口加分页参数

改完之后，按这个顺序告诉我就行，不用写文档：

2. 哪些地方是**纯样式**（我直接映射到 CSS 令牌/组件）

> 保持所有玩家页面是同一个产品：同样的侧栏、同样的卡片、同样的间距节奏。

## 7. 本地预览

双击 `index.html` 就能看，不需要服务。如果浏览器对本地文件限制较多，起一个静态服务：

```bash
cd prototype
python3 -m http.server 8090
# 打开 http://127.0.0.1:8090/index.html
```

`scenes` 是相对软链接；如果把 `prototype/` 单独拷走，图片会加载失败并自动回落到渐变封面。需要真实场景图时，把 `SillyTavern/default/content/backgrounds` 一起带上，或替换 `scenes` 指向的目录。

每个页面右下角有一个「← 原型总览」浮标（移动端缩成圆形），只在原型里存在，交付实现时删掉 `<a class="p-proto-back">` 那一行和 `proto.css` 里的 `.p-proto-back` 即可。

共享交互状态由 `platform.js` 提供；设置页另有一段约 30 行的滚动高亮脚本（目录跟随滚动），真实实现时可以直接搬进 `renderSettings`。

这份原型放在 `酒馆/prototype/`，不在 SillyTavern 仓库里，不会影响构建，也不会被提交到上游。
